# F9.139 — Medios de pago canónicos: Efectivo se va, BBVA es el default, los bancos no se inventan

## Contexto

Tres defectos independientes que comparten síntoma ("aparecen bancos que no configuré"):

1. **`src/vistas/Comprobantes.tsx:378`** — `banco: 'Efectivo' as const`. Hardcodeado en el
   preload del alta desde comprobante (ramas 2/3). *Todo* movimiento nacido de un comprobante
   arranca con Efectivo. No lee config, no hay default configurable.
2. **`src/datos/resumenesTarjeta.ts:267, 307, 345`** — `banco: resumen.banco || null`, y en
   `:305, :343` el mismo string va además a `subcategoria`. `resumen.banco` es texto libre que
   devuelve el modelo leyendo la carátula del PDF (`functions/src/index.ts:1229`,
   `banco: resumen.banco || banco`). Si el resumen dice "BBVA Argentina", eso entra crudo.
   Nadie lo contrasta contra `config/familia.bancos`.
3. **`src/vistas/AltaMovimiento.tsx:191`** — `config.bancos.map(...)` sin filtrar `oculto`,
   mientras `src/vistas/EditarMovimiento.tsx:98` usa `mediosVisibles(config.bancos)`. Efectivo
   está `oculto: true`, así que hoy **se ofrece al dar de alta y se esconde al editar**.

El patrón correcto ya existe en el repo, a 100 líneas del defecto 2:
`src/datos/resumenesTarjeta.ts:409` usa `tarjetaMeta.banco`, que sale de `config.tarjetas` y es
canónico por construcción.

## Decisiones tomadas (del dueño, no inferidas)

- Efectivo deja de existir como medio; los movimientos históricos con `banco: 'Efectivo'`
  migran a `'Mercado Pago'` (que es lo que ya se mostraba vía `aliasDe`).
- Sin banco detectable → el medio marcado por defecto. Hoy: BBVA.
- El default es un flag editable desde Perfil › Medios de pago, no una constante.
- `"BBVA Argentina"` → `BBVA`. **Es el único alias conocido.** No se construye matcheo difuso:
  tabla explícita, y lo que no está en la tabla no se adivina.

## Decisión ABIERTA — resolver antes de empezar

`actualizarMediosPago` (`functions/src/index.ts:1877`) hace full-replace y escribe el array tal
cual (`bancos: medios`, `:1917`), validando campo por campo. `porDefecto` va a persistir **sin
tocar functions**, pero sin validación server-side de "exactamente uno".

- **Opción A (solo hosting):** validar "exactamente un `porDefecto`" en el cliente, antes de
  llamar. Deploy = `--only hosting`. Riesgo: cero defaults o dos defaults si algo escribe la
  config por otra vía.
- **Opción B:** agregar la validación al callable. Deploy = `--only hosting,functions:actualizarMediosPago`.

Sin respuesta, implementar **A** y dejar el hueco anotado en `docs/CLAUDE.md`.

```ts
// F9.139 — el medio que se asume cuando no hay ninguno detectable. Cae al primero de la
// lista si nadie está marcado, para no devolver undefined y escribir null en `banco`.
```
