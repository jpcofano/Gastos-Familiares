## 1. Objetivo (pedido del dueño)

Un comprobante llega propuesto como **rama 2** (badge *"Obligación de Julio 2026"*) contra un gasto esperado que **no corresponde** — ej.: una transferencia a *Bodegon El Globito Srl* asociada a una obligación mensual.

Hoy las únicas salidas son *"Asignar a otro gasto"* (picker: lo manda a **otro** esperado) y *"Revisar y cargar"* (lo carga **con** el vínculo equivocado). Falta:

1. **"Asignar como movimiento nuevo"** — cargarlo como gasto suelto, sin `itemEsperadoId`.
2. **Que aprenda** — que ese payee no vuelva a proponerse contra ese gasto esperado.

### Parte 0 — La card nunca dice A QUÉ gasto esperado va a vincular (bloqueante)

### Parte 1 — Callable nueva `desvincularDestinoItem` (`functions/src/index.ts`)

Ubicar junto a `upsertDestino` (después de la línea 3043). Copiar **exactamente** el bloque de auth admin de `upsertDestino:2979-2985`.

```ts
// F9.109 — desaprendizaje explícito: el usuario dijo "este payee NO es ese gasto esperado".
// Sólo saca el vínculo item↔destino; NO borra el doc, NO toca categoría/confianza (el prefill
// de categoría aprendido sigue sirviendo: matchPorDestino cae a rama 3). No crea docs.
export const desvincularDestinoItem = onCall(
  { region: 'southamerica-east1' },
  async (request) => {
    // …auth admin idéntico a upsertDestino…
    const { raws, itemEsperadoId } = (request.data ?? {}) as { raws?: unknown; itemEsperadoId?: string };
    if (!Array.isArray(raws) || raws.length === 0) throw new HttpsError('invalid-argument', 'raws requerido');
    if (!itemEsperadoId || typeof itemEsperadoId !== 'string') throw new HttpsError('invalid-argument', 'itemEsperadoId requerido');

    const limpiados: string[] = [];
    for (const raw of raws) {
      if (typeof raw !== 'string' || !raw.trim()) continue;
      const parsed = normalizarDestino(raw);
      if (!parsed) continue;
      const ref  = db.collection('destinos').doc(idDestinoNorm(parsed.norm));
      const snap = await ref.get();
      if (!snap.exists) continue;                                   // no crear
      if (snap.data()?.itemEsperadoId !== itemEsperadoId) continue; // no pisar otro vínculo
      await ref.update({ itemEsperadoId: FieldValue.delete(), actualizadoEn: FieldValue.serverTimestamp() });
      limpiados.push(ref.id);
    }
    console.log(`[desvincularDestinoItem] item=${itemEsperadoId} → limpiados=[${limpiados.join(',')}] (por ${email})`);
    return { ok: true, limpiados };
  },
);
```

Notas de implementación:
- Es **idempotente** y no-op si el destino no tenía ese vínculo: se puede llamar siempre, sin averiguar antes el origen.
- `raws` se manda en el mismo orden de precedencia que usa `aprenderDestino:660` y `matchPorDestino:499-500`: `destinoCbu, destinoCuit, destinoAlias, destinoNombre`. Así también se limpia el **alias por nombre** que `aprenderDestino:701-723` crea aparte.
- Cero cambios en `aprenderDestino`: al guardarse el movimiento sin `itemEsperadoId`, el trigger no re-agrega el vínculo (`index.ts:678`, sólo escribe si hay item), y sí refresca la categoría. Ese es el comportamiento deseado.

### Parte 4 — Aprendizaje (fail-soft), al guardar

Enganchar en `onGuardarPayload` (645-650): **primero** se guarda el movimiento; sólo si `res.ok`, se corrige el aprendizaje. Nada de esto puede tirar ni bloquear.

```ts
onGuardarPayload={async (payload) => {
  const res = await cargarMovimientoDesdeComprobante(comp.id, payload);
  if (res.ok && desvincular && itemEsperadoEfectivo) {
    void corregirAprendizaje(itemEsperadoEfectivo);  // fire-and-forget, try/catch adentro
  }
  return { ok: res.ok, error: res.ok ? undefined : res.error };
}}
```

`corregirAprendizaje(itemId)` hace dos cosas, cada una en su propio `try/catch`:

**(a) Destino** — siempre (idempotente, no-op si no aplica):

```ts
await desvincularDestinoItem([d.destinoCbu, d.destinoCuit, d.destinoAlias, d.destinoNombre], itemId);
```

**(b) `matchTexto`** — sólo si `pm.origenDestino !== true` (es decir, matcheó por texto). Agregar el payee a `excluye` del ítem:

```ts
const item  = items.find(i => i.id === itemId);
const texto = [d.comercioRazonSocial, d.destinoNombre].filter(Boolean).join(' ').toLowerCase();
const token = (payeeDeDatos(d) ?? '').trim().toLowerCase();
if (item?.matchTexto && token && texto.includes(token) && !item.matchTexto.excluye.includes(token)) {
  await actualizarItemEsperado(itemId, {
    matchTexto: { incluye: item.matchTexto.incluye, excluye: [...item.matchTexto.excluye, token] },
  });
}
```

Reglas de esta rama:
- `texto` reproduce exactamente lo que evalúa `matchConEsperados:193-196`; el `token` tiene que estar **contenido** ahí o la exclusión no serviría de nada → si no está contenido, no se escribe nada (no inventar tokens).
- Nunca se toca `incluye`, sólo se **agrega** a `excluye`. La corrección queda visible y editable en *Config → Esperados*.
- Si falla: `console.error` + advertencia chica en la card (`El movimiento se guardó, pero no se pudo registrar la corrección.`). El movimiento ya está guardado y así queda.
