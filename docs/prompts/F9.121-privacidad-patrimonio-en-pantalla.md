> Auditado sobre `origin/main` en `1dcb685` (F9.107 — MoneyInput es-AR). Línea base declarada de `npx tsc --noEmit`: **41 errores** — verificarla antes de tocar y no moverla.

## Problema

F9.119/F9.120 dejaron el modo privacidad funcionando en Resumen, Inicio y en el informe PDF de Patrimonio. **La solapa Patrimonio en pantalla quedó sin cubrir**: es la única vista donde prender el modo no tapa nada, y es justo la que más expone (total del portfolio, valuación por posición, pérdidas en dólares por escenario, aportes y retiros).

Peor que no tener el modo: tenerlo prendido, ver el ojo tachado en el header y creer que los montos están tapados cuando no lo están.

## Alcance

### Sección 1 — Un solo helper local

Agregar en `Patrimonio.tsx`, junto a `fmtUsd`/`fmtArs`:

```ts
import { usePrivacidad, fmtPct, BasePrivacidad } from '../contexto/PrivacidadContext';

// F9.121 — un solo lugar decide si el número sale en plata o en %.
function useDinero(base: number) {
  const { privado } = usePrivacidad();
  return {
    privado,
    // Valor absoluto → % de la base, o el monto en USD.
    usd: (n: number) => privado ? fmtPct(n, base) : fmtUsd(n),
    // Gemelo en pesos: con el modo activo devuelve '' y la línea NO se renderiza.
    ars: (n: number, tc: number) => privado ? '' : fmtArs(n, tc),
  };
}
```

No tocar `fmtUsd`/`fmtArs`: siguen siendo funciones puras y las usa el helper. `fmtPct` ya resuelve base cero, signo y `<1%` / `>-1%` (F9.120); no reimplementar nada de eso acá.

Cada componente de la tabla de arriba llama `const $ = useDinero(base)` y reemplaza `fmtUsd(x)` → `$.usd(x)`, `fmtArs(x, tc)` → `$.ars(x, tc)`.

### Sección 2 — La base es una sola: el portfolio invertible

**Base = `M.total`** (portfolio invertible), etiqueta **"% del portfolio invertible"**.

No es `patrimTotal` (`:817` = `M.total + fijosUsd`). Razón: la vista ya muestra chips de porcentaje calculados sobre `M.total` (`pesoEnCartera`, `pct(x / total)` en `:546`, `:1261`). Si la base del modo privacidad fuera otra, el monto convertido y el chip de la misma fila mostrarían dos porcentajes distintos del mismo número.

Consecuencias aceptadas:

- **"Portfolio invertible" en el hero (`:836`) renderiza `100%`.** Es el valor que define la base. Se deja visible en vez de ocultarlo para no dejar un hueco en el hero negro y para que la base se lea sin ambigüedad.
- **"Patrimonio total" (`:858`) puede superar 100%** (p. ej. `118%`). Es correcto y significa "los activos fijos suman 18% sobre el invertible". Con el rótulo de base al pie del hero, se lee bien.

Si Code considera que `100%` en el hero es ruido, puede reportar la alternativa (ocultar la fila y dejar solo el rótulo de la base) — pero **no cambiarlo por iniciativa propia**.

El componente `BasePrivacidad` va **una sola vez**, debajo del hero de `ResumenTab` y también en la cabecera de las otras solapas que muestran plata (`TenenciasTab`, `RiesgoTab`, Plan). Un porcentaje sin base declarada arriba es ruido.

### Sección 3 — Casos que no son un reemplazo mecánico

| Sitio | Regla |
|---|---|
| `:839`, `:861` (gemelos ARS del hero) | Con `$.ars()` devolviendo `''`, **no renderizar el `<div>`** — no dejar una línea vacía ocupando alto. |
| `:844` delta vs corrida previa | Ya muestra `(+3%)` al lado, sobre una base distinta (total de la corrida anterior). En privado: **ocultar el absoluto y dejar solo el paréntesis**. Nunca dos porcentajes distintos del mismo número. |
| `:546`, `:1261`, `:1336`, `:1562`, `:1581` | Mismo criterio: donde ya hay un `pct()` en la misma frase, el absoluto desaparece y el `pct()` queda. |
| `:655` tolerancia declarada | `fmtUsd(-topes.toleranciaCaidaPct * titular.total)` → en privado es literalmente la tolerancia declarada en %. Correcto que salga como %. |
| `:1151` nominales (`cant.toLocaleString`) | **Se ocultan.** Una cantidad de nominales revela el tamaño de la posición y no tiene conversión a % que signifique algo. Mostrar solo el ticker. |
| `:1377` `fmtDelta` | La rama `kind === 'usd'` pasa por `$.usd`. La rama `pp` **no se toca**: puntos porcentuales no son plata. |
| `:2398` `AportesRetirosCard` | Reemplazar el literal por `$.usd(f.montoUsd)`, conservando el `+`/`−` y el color por tipo. |
| `:865` TC del día | **No se tapa.** El tipo de cambio es público y no dice nada del patrimonio. |

### Sección 4 — Toggle

Botón del ojo en el header de la vista, al lado de "Actualizar posiciones" (`~:3986`), **copiando el patrón existente**: `Resumen.tsx:1105-1122` / `Dashboard.tsx:821-838`. Mismo icono (`eye` / `eye-off`), mismos colores, mismo `aria-label` ("Mostrar montos" / "Ocultar montos").

Patrimonio no tiene segmentado ARS/USD, así que no hay control que deshabilitar (a diferencia de Resumen e Inicio).

El estado sigue viniendo del `PrivacidadProvider` de `AppShell.tsx:116` — **no crear estado local**. Prenderlo en Inicio y navegar a Patrimonio tiene que llegar tapado.

### Sección 5 — Relación con el checkbox del informe PDF

El informe tiene su propio checkbox `sinMontos` (`:799`, `:984`) que viaja como `soloPorcentajes` (`:3962`). **Quedan independientes y así se documenta en el código con un comentario de una línea.**

Son dos decisiones distintas: el modo de pantalla es efímero (alguien mirando al lado); el PDF es un archivo que se entrega y sobrevive. Acoplarlos haría que tapar la pantalla cambie silenciosamente el contenido de un archivo que ya generaste, o al revés.

## Fuera de alcance

- El informe PDF (ya resuelto en F9.120).
- Los `MoneyInput` de los formularios de alta/edición (manuales, activos fijos, flujos): son campos de edición, no de exhibición. Se tapan solos porque el modal no está abierto mientras mostrás la pantalla.
- El textarea de prompts de la solapa Research: es un artefacto para copiar y pegar afuera, y tiene que llevar los montos reales para servir. Anotado como decisión, no como olvido.
- Persistencia del modo: sigue sin persistir, por la razón de F9.120.

5. **Continuidad entre vistas:** prender en Inicio → navegar a Patrimonio → sigue tapado; apagar en Patrimonio → volver a Inicio → destapado.
