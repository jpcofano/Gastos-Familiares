# F9.128 — `bloqueDe`: la denominación del bono no sale de `moneda_origen`

**Base:** origin ≥ `b97cd7a`. **Deploy:** `--only hosting`.
**Se aplica ANTES de F9.127 §1.** F9.127 §3 valida consistencia contra la salida de `bloqueDe`; si
la referencia está mal, el cross-check no prueba nada.

---

## El hallazgo

Detectado en la auditoría de F9.127 §0, que buscaba otra cosa. `moneda_origen` es **la moneda en la
que la posición viene expresada en el archivo de origen, no la denominación del instrumento.** El
mismo bono aparece con `USD` y con `ARS` según la fila:

```
GD30  bono USD → soberanoAr        GD30  bono ARS → rentaFijaPesos
GD35  bono USD → soberanoAr        GD35  bono ARS → rentaFijaPesos
BPOC7 bono USD → soberanoAr        BPOC7 bono ARS → rentaFijaPesos
TZXM7 bono USD → soberanoAr        DICP  bono USD → soberanoAr
```

Dos errores simétricos: soberanos hard-dollar cayendo en `rentaFijaPesos` (USD 1.795), y CER en
pesos —TZXM7, DICP, TX26, LECAPSA— cayendo en `soberanoAr` (USD 10.612). Son ~12% del invertible en
el bloque equivocado.

**Qué NO se mueve:** la exposición argentina agregada (71,5%). Los dos errores caen dentro de
Argentina, así que el titular es correcto. Lo que está mal es el reparto interno — y por lo tanto la
beta que cada escenario le aplica a esa plata. Decilo así en la UI cuando aparezca el cambio: el
número grande no se movió, se movió su composición.

## §1 — Tabla declarada de denominación

En `src/datos/patrimonioRiesgo.ts`, arriba de `bloqueDe`:

```ts
// F9.128 — `moneda_origen` describe cómo viene expresada la FILA en el archivo de origen, no en qué
// moneda está denominado el INSTRUMENTO: el mismo GD30 aparece con USD en una cuenta y ARS en otra.
// Clasificar por ese campo mandaba soberanos hard-dollar a rentaFijaPesos y CER en pesos a
// soberanoAr — ~12% del invertible con la beta equivocada aplicada en cada escenario.
// La única señal confiable es el ticker. Va como tabla explícita y no como regex de prefijos para
// que se pueda leer, auditar y corregir sin desarmar una expresión regular.
export type Denominacion = 'hard' | 'pesos';

export const DENOMINACION_SOBERANO: Record<string, Denominacion> = {
  GD30: 'hard', GD35: 'hard', GD38: 'hard',
  BPOC7: 'hard', BPOD7: 'hard',
  TX26: 'pesos', TZXM7: 'pesos', TZSU2: 'pesos',
  DICP: 'pesos', LECAPSA: 'pesos',
  // completar con lo que salga de §0 punto 1. Si un ticker de la corrida no está acá, NO inventes
  // su denominación: que caiga en el fallback y aparezca reportado.
};

// Fallback SOLO para instrumentos que todavía no están en la tabla. Documentado porque es una
// heurística sobre nomenclatura del mercado local, no una verdad: GD/AL/BPO/BPY son ley extranjera
// o local en dólares; TX/TZX/T*/DICP/PARP/LECAP/BONCER ajustan por CER o son a tasa en pesos.
export function denominacionDe(ticker: string): { den: Denominacion; inferida: boolean } {
  const t = ticker.toUpperCase();
  const tabla = DENOMINACION_SOBERANO[t];
  if (tabla) return { den: tabla, inferida: false };
  if (/^(GD|AL|AE|BPO|BPY)\d/.test(t)) return { den: 'hard', inferida: true };
  if (/^(TX|TZX|TZ|DIC|PAR|LECAP|BONCER|S\d)/.test(t)) return { den: 'pesos', inferida: true };
  return { den: 'pesos', inferida: true };  // ver nota abajo
}
```

**Sobre el default del fallback:** cae en `pesos` deliberadamente. Un instrumento AR sin identificar
es más probablemente en pesos, y el error es conservador: `rentaFijaPesos` tiene la beta más
castigada, así que un desconocido mal clasificado **sobreestima** el riesgo en vez de esconderlo. Un
sistema de riesgo tiene que fallar hacia el lado incómodo. Igual, toda inferencia con
`inferida: true` se reporta en pantalla — ver §3.

## §2 — `bloqueDe` usa la tabla

Reemplazar la rama que hoy decide por `moneda_origen` para `tipo` bono/on con riesgo AR:

```ts
  if (p.pais_riesgo === 'AR' && (p.tipo === 'bono' || p.tipo === 'on')) {
    return denominacionDe(p.ticker).den === 'hard' ? 'soberanoAr' : 'rentaFijaPesos';
  }
```

**Ojo con las ON corporativas.** El bloque se llama `soberanoAr` y una ON corporativa en dólares no
es soberana. Si en la corrida hay ONs corporativas (`sector: corporativo_usd` apareció en §0),
**paráme y reportá** antes de meterlas ahí: puede hacer falta un bloque nuevo, y eso es otra
decisión, no un detalle de implementación.

No toques nada más de `bloqueDe`. Las ramas de acciones, cripto, cash y global quedan como están.

## §3 — Visibilidad de las inferencias

En la solapa Riesgo, junto al desglose por bloque: si alguna posición se clasificó con
`inferida: true`, listarlas con su ticker y el bloque asignado.

No es un warning con signo de exclamación: es una línea informativa que dice qué se dio por sentado.
El objetivo es que la próxima vez que aparezca un instrumento nuevo, se vea antes de que contamine
un escenario durante seis meses en silencio — que es exactamente lo que acaba de pasar.
