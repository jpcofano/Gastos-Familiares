## §1 — Unidad única en el benchmark (fracción 0–1)

`pesoPct` está persistido en Firestore en decenas de docs como porcentaje 0–100. No se migra:
se convierte al leer. Los campos de `FilaBenchmark` pasan a ser **fracción**, y se renombran —
un campo llamado `...Pct` que guarda una fracción es exactamente la trampa que produjo este bug.

## §2 — Resolución especie→ticker por patrón, no por clave exacta

`importarMappingSeed` escribe docs con clave = patrón normalizado (`"ypf"`, `"pampa energia"`).
`parsearFichaCafci` busca con `doc(normalizarEspecie(especieRaw)).get()`, o sea la clave es el
nombre COMPLETO (`"pampa energía s.a."`). Casi ningún seed pega.

### `functions/src/index.ts` — `parsearFichaCafci`

Antes del `for (const item of items)`, cargar el diccionario de mappings **una sola vez** por
corrida y armar la lista de patrones ordenada por longitud descendente:

```ts
  // F9.122 — el seed de mappings guarda PATRONES ("ypf", "grupo galicia"), no nombres completos.
  // La resolución era por clave exacta contra el nombre entero de la especie, así que el seed casi
  // nunca pegaba. Se resuelve en dos etapas: exacta primero (respeta lo aprendido y lo cargado a
  // mano), patrón después. Una sola lectura de la colección por corrida — nunca por posición.
  const mappingSnap = await db.collection('cafciMapping').get();
  const mapExacto = new Map<string, { ticker: string | null; categoria?: string }>();
  for (const d of mappingSnap.docs) {
    mapExacto.set(d.id, d.data() as { ticker: string | null; categoria?: string });
  }
  // Patrones con ticker resuelto, del más largo al más corto: "grupo galicia" gana sobre "galicia",
  // y "ypf energia electrica" (ON) nunca se come el match de "ypf".
  const patrones = [...mapExacto.entries()]
    .filter(([, v]) => !!v.ticker)
    .sort((a, b) => b[0].length - a[0].length);
```

Reemplazar el bloque `else { const mappingSnap = await db.collection('cafciMapping').doc(norm).get(); ... }`
por:

