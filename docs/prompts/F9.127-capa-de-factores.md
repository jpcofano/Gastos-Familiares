# F9.127 — Capa de factores de riesgo

**Base:** origin ≥ `3450d24` (F9.123). **Deploy:** `--only hosting` salvo que §2 requiera reglas.
**No depende de F9.124/F9.126.** Se puede aplicar antes, después o en paralelo.

Numeración: F9.126 queda reservado para el informe anual (F9.124 §B diferido).

---

## Por qué

`Bloque` tiene seis valores y `accionesAr` es uno solo. Ninguna métrica construida sobre esa grilla
puede ver que **el 87,7% de la renta variable argentina de la cartera es energía** (medido con la
base comparable de F9.122.1 §B: TRAN 22,9 + YPFD 20,9 + PAMP 20,9 + VIST 13,0 + TGSU2 6,8 + CEPU 3,0
+ ECOG 0,2). Para el sistema actual TRAN y GGAL son el mismo animal.

Peor: el escenario `energia_ar` castiga a TRAN, TGSU2, CEPU, ECOG, YPFD, PAMP y VIST con el mismo
−30%. Son **dos factores distintos**. Las reguladas dependen de una decisión tarifaria; las de
upstream, del precio del crudo y el gas. Un congelamiento tarifario destroza a TRAN y apenas toca a
VIST; un crudo a 45 hace lo inverso. Colapsarlas da un número que no es ni el bueno ni el malo.

Este prompt agrega la capa de factores y la concentración por factor. **No** incluye el motor de
declaración (declarada / derivada / emergente): eso es F9.128, y depende de esto.

## §1 — `Factor` y `factorDe()`

En `src/datos/patrimonioRiesgo.ts`, al lado de `bloqueDe` (misma casa, mismo estilo):

```ts
// F9.127 — Factor de riesgo: qué mueve el precio, no qué instrumento es. `Bloque` responde
// "dónde está la plata"; `Factor` responde "qué la hace subir o bajar". Son ortogonales: un bono
// soberano y una acción argentina son bloques distintos y el MISMO factor país, y por eso la
// cartera puede verse diversificada por bloque y ser una sola apuesta.
export type Factor =
  | 'energia_ar_regulada'   // transporte, distribución, generación: manda la tarifa
  | 'oil_gas'               // upstream: manda el precio del crudo y el gas
  | 'banco_ar'
  | 'industria_ar'
  | 'infraestructura_mercado'// BYMA y afines: manda el volumen operado
  | 'soberano_ar_hard'      // GD/BPO: manda el riesgo país
  | 'soberano_ar_pesos'     // LECAP/CER/TX: manda la tasa y la inflación
  | 'cripto'
  | 'global_dm'
  | 'cash'
  | 'sin_clasificar';
```

`factorDe(p: Posicion): Factor` resuelve en este orden, **y el orden importa**:

1. **Override manual por ticker** (§2). Gana siempre. Es el único lugar donde se resuelven los casos
   ambiguos, y tiene que ganarle a cualquier heurística.
2. `tipo === 'cripto'` → `cripto` · `tipo === 'cash'` → `cash`.
3. `pais_riesgo !== 'AR'` → `global_dm`.
4. Renta fija AR: `tipo` bono/on + moneda dura → `soberano_ar_hard`; pesos/CER →
   `soberano_ar_pesos`. **Definí el criterio de moneda explícitamente en el código**, no lo dejes
   implícito en el ticker.
5. Renta variable AR: por `sector` según lo que devuelva §0.
6. Si nada resuelve → `sin_clasificar`. **Nunca inventes un default plausible**: una posición mal
   clasificada en silencio es peor que una sin clasificar a la vista.

### Los ambiguos son el punto, no el borde

**PAMP es genuinamente los dos factores**: generación eléctrica regulada *y* upstream de gas.
Asignarle uno solo es una decisión, no un dato. En v1 se asigna uno y se marca como ambiguo:

```ts
// F9.127 — tickers cuya exposición real se reparte entre dos factores. En v1 se les asigna el
// dominante y se los marca: la app tiene que decir "esto es una simplificación", no fingir
// precisión. Repartir el valorUsd entre factores es F9.128 si hace falta.
export const FACTOR_AMBIGUO: Record<string, { asignado: Factor; tambien: Factor; nota: string }> = {
  PAMP: { asignado: 'oil_gas', tambien: 'energia_ar_regulada',
          nota: 'Upstream de gas y generación eléctrica. Se asigna oil_gas por peso del negocio.' },
  // completar con lo que salga de §0
};
```

La UI muestra un indicador junto al ticker ambiguo, con la nota en el `title`. **No se esconde.**

## §2 — Override por ticker

Colección `factoresTicker/{TICKER}` → `{ factor: Factor, origen: 'auto' | 'manual', nota?: string }`.
Mismo patrón que `cafciMapping`, que ya funcionó — **con las dos lecciones aprendidas**:

- **No persistir clasificaciones negativas.** Un `sin_clasificar` guardado se vuelve cache negativo y
  fosiliza el miss. Fue el bug de F9.122 §3; no lo repitas.
- Lectura **una sola vez por render**, no un `get()` por posición.

Semilla desde el mapa de §1 con un botón `Importar factores`, junto a los de CAFCI. Idempotente,
`merge: true`, y **nunca pisa `origen: 'manual'`**.

## §3 — Concentración por factor

```ts
// F9.127 — La lección de F9.122.1 §B: un porcentaje sin denominador declarado induce a error.
// Acá se exponen los dos, siempre juntos, porque responden preguntas distintas y confundirlos fue
// exactamente el bug que produjo la tabla de benchmark de julio.
export type ExposicionFactor = {
  factor: Factor;
  usd: number;
  pctInvertible: number;   // sobre el patrimonio invertible total
  pctBloque: number;       // sobre su propio bloque
  tickers: string[];
  ambiguos: string[];      // subconjunto marcado en FACTOR_AMBIGUO
};
```

Y la métrica transversal, que es la que ningún indicador actual muestra:

```ts
// F9.127 — Exposición argentina agregada, atravesando bloques. Renta fija AR y renta variable AR
// no son dos apuestas: si Argentina repricea, se mueven juntas. La vista por bloque las presenta
// como diversificación y eso es una ilusión de encuadre.
export function exposicionArgentina(posiciones: Posicion[]): {
  usd: number; pctInvertible: number; porFactor: ExposicionFactor[];
};
```

Card nueva en la solapa **Riesgo**, arriba de los escenarios: exposición argentina total como
titular, desglose por factor debajo, y HHI + nombres efectivos calculados **por factor**, no por
ticker. El HHI sobre los 10 tickers de RV AR da ~1.678 (≈6 nombres efectivos) y se lee como
"diversificado"; sobre factores va a dar otra cosa, y esa otra cosa es la verdad.

**Respetar modo privacidad** (F9.121 §3): con `priv` activo, montos fuera, porcentajes adentro.

## §4 — Escenarios por factor

Agregar a `ESCENARIOS_IDIOSINCRATICOS`, con `porFactor()` análogo a `porBloque()`:

- **Congelamiento tarifario** → `energia_ar_regulada` −35%, `oil_gas` −10%.
- **Crudo a la baja** → `oil_gas` −30%, `energia_ar_regulada` −5%.
- **Normalización argentina** (upside; hoy el único escenario positivo es `rally` global, y mostrar
  solo el downside es información sesgada — el propio código lo dice en el comentario de `rally`) →
  `soberano_ar_hard` +25%, `banco_ar` +40%, `energia_ar_regulada` +30%, `oil_gas` +15%.
- **Nombre único −40%** aplicado a la mayor posición individual, calculada, no hardcodeada.

**No toques los escenarios existentes.** `energia_ar` queda como está: comparabilidad histórica.
Documentá en su `descripcion` que quedó superado por los dos nuevos.
