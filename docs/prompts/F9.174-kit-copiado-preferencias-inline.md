# F9.174 — Kit copiado en el repo: preferencias inline que pisan el tema oscuro

**Alcance:** `src/design-system/ui_kits/mobile/` (la copia del UI kit dentro del repo). **La
app no está afectada** — ver §1. Sin cambios de modelo ni de Rules. Deploy: no requiere.

---

## §1 — Primero el hallazgo negativo: la app está limpia

Busqué `style.setProperty('--…')` en todo `src/` a `493f829`. Los 11 resultados están **todos**
en `src/design-system/ui_kits/mobile/index.html`, que es la copia del UI kit. **Ningún archivo
de la app escribe custom properties inline en `<html>`.** El selector de paletas de gráficos
del producto (F9.55, `graficosPrefs.ts`) resuelve por índice, no pisando tokens.

Conclusión: el bug de abajo **no afecta a los usuarios**. Esto es higiene del kit copiado, que
además es la referencia visual que se consulta al implementar. Si está mal, manda mal.

## §2 — El bug, para que quede registrado en el repo

El panel de tweaks del kit aplica las preferencias de **paleta** y **acento** escribiendo
custom properties inline en `<html>`:

```js
r.setProperty('--gf-emerald', a.base);   // #065f46, valor CLARO
r.setProperty('--gf-income', inc);
r.setProperty('--gf-out', out);
```

Esos siete tokens (`--gf-emerald`, `--gf-emerald-deep`, `--gf-emerald-50`, `--gf-income`,
`--gf-out`, `--color-accent`, `--color-primary*`, `--color-focus-ring`) son justamente los que
`html[data-theme="dark"]` remapea (F9.169 §3). **Lo inline le gana a todo selector**, así que
en modo oscuro quedaban clavados en su valor claro: el rótulo `Hoy` a 3,15:1 y el label activo
del bottom-nav a 2,25:1, con los tokens resolviendo perfecto y nada fallando a la vista.

Es la trampa que F9.172 §1 dejó anotada como primera candidata, y la razón por la que
`html[data-theme="dark"]` no alcanzaba: no es un problema de especificidad, es que lo inline
está fuera de la cascada.

**No alcanza con "no escribir el default"**: con cualquier opción elegida el problema vuelve.

## §3 — El arreglo

Las preferencias que pisan tokens del tema **no van inline**: van a una hoja `<style>` acotada
a claro, así valen en claro y en oscuro manda el tema.

```js
const cssVar = (id, decls) => {
  let el = document.getElementById(id);
  if (!decls) { if (el) el.remove(); return; }
  if (!el) { el = document.createElement('style'); el.id = id; document.head.appendChild(el); }
  el.textContent = `html:not([data-theme="dark"]){${decls}}`;
};
```

- `paleta` → `cssVar('tw-palette', '--gf-income:…;--gf-out:…')`
- `acento` → `cssVar('tw-accent', …)` con los siete tokens
- `--gf-cat-*` (paleta de gráficos) y `--font-base` **siguen inline**: son independientes del
  tema.

De paso: la opción "Marca" de la paleta declaraba `#0c8f62` / `#f97316`, que no son los valores
de `--gf-income` / `--gf-out`. Corregida a `#047857` / `#d97706` — así "Marca" queda
seleccionada al abrir, que es lo que el default dice.
