# F9.124 — Informe mensual en PDF (cierra el placeholder F9.14)

**Base:** origin HEAD `1c38f1e`. **Deploy:** `--only hosting` (frontend puro, sin callables nuevos).
Aplicar **después** de F9.123, porque reusa `escalaDia` para el gráfico embebido.

---

## Qué cierra

`src/vistas/Dashboard.tsx` tiene desde F9.14 un botón "Compartir informe" que abre un
`<Message kind="wait">` diciendo *"está en definición (PDF, email o link)"*. Esto lo resuelve: **PDF
generado en el cliente + share sheet nativa**, con fallback a descarga.

Nada de email ni link: el email lo pone el sistema operativo desde el share sheet, y un link exigiría
Storage público con expiración — superficie de seguridad nueva para un informe que se regenera en
dos segundos desde datos que ya están cargados.

## Decisiones tomadas (no reabrir sin motivo)

1. **Motor: pdfmake**, el mismo de `src/datos/patrimonioInforme.ts`. Ya está en `package.json`
   (`^0.2.12`), ya está resuelto el import dinámico con `vfs_fonts`, y ya hay convenciones de estilos
   (`h1`, `h2`, `tableHeader`, `note`, `defaultStyle`). **Auditá ese archivo antes de escribir una
   línea** y copiá los helpers (`h1`, `h2`, `tableOf`, `note`, `pageBreak`, `fmtFecha`), no los
   reinventes.
2. **No se archiva en Storage ni en Firestore.** Diferencia con el informe de patrimonio: aquel
   documenta una *corrida* —un estado que no se puede reconstruir después— y por eso se archiva. El
   informe mensual es una proyección de datos vivos que siguen en Firestore; archivarlo genera
   copias que se desactualizan y contradicen la app.
3. **Hereda modo privacidad como opción explícita**, con el mismo patrón de F9.119/F9.120: el
   parámetro `soloPorcentajes` sombrea el formateador de montos y **es independiente del toggle de
   pantalla**. Se declara en la portada y en el nombre del archivo (`-sin-montos`).
4. **Alcance de datos = el que ya tiene la vista.** El PDF no consulta nada que el Dashboard no
   tenga cargado. Si un dependiente abre el Dashboard, su informe sale con su alcance. Sin reglas
   nuevas, sin queries nuevas.

## Decisiones abiertas — resolver antes de implementar

- **§A. ¿Entra la sección de gastos fijos (checklist del mes)?** Es el mayor aporte respecto de la
  pantalla: "qué falta pagar" es la pregunta que uno se lleva del mes, y hoy vive en otra solapa.
  Pero obliga a levantar `itemsEsperados` + estado de match dentro del generador, que hoy el
  Dashboard no carga. **Mi recomendación: sí, en v1.** Si sale caro, se difiere a F9.125 y el
  informe v1 sale sin §6.
- **§B. ¿Mensual solamente, o también anual?** El botón está en la vista mensual. La anual tiene
  `DashAnual` completo y el informe saldría casi gratis reusando el mismo motor.
  **Mi recomendación: mensual en v1**, anual como F9.125 una vez que el motor esté probado.

Contestá A y B antes de que Code arranque.


### Secciones

1. **Portada** — "Gastos Familiares · Informe mensual", mes en largo (`agosto 2026`), moneda base y
   TC usado, fecha/hora de generación. Si `soloPorcentajes`, línea explícita: *"Variante sin montos:
   cada valor se expresa como % del gasto del mes."* con la base declarada.
2. **Resumen** — tabla de 2 columnas: ingresos, salidas, balance, movimientos, promedio diario, días
   con gasto, % fin de semana, banco dominante. Debajo, la línea de contexto:
   `vs mes anterior {vsMesAnteriorPct}% ({vsMesLabel})` y `d.lecturaRapida` en itálica.
3. **Por categoría** — `tableOf(['Categoría','Monto','%'])` desde `d.categorias`, ordenado desc.
   Cerrar con la línea "Top 3 categorías: {d.top3Pct}% del gasto del mes".
4. **Por subcategoría** — `d.subcategorias`, mismo formato. Máximo 15 filas; si hay más, fila
   "Resto (N)" con el agregado. **No prorratear ni descartar en silencio.**
5. **Evolución diaria** — barras como **SVG embebido** (`{ svg: '<svg …>' }`; pdfmake lo soporta
   nativamente). Reusar exactamente la lógica de escala de F9.123 (`escalaDia`, `hayRecorte`,
   `diasRecortados`) — extraerla a un helper exportado desde `Dashboard.tsx` o, mejor, a
   `src/datos/agregados.ts` para que el gráfico de pantalla y el del PDF no puedan divergir. Es el
   patrón gemelo de siempre: una sola implementación, dos consumidores. Si hay recorte, la misma
   nota al pie que en pantalla.
6. **Gastos fijos del mes** *(condicional a §A)* — tabla `Ítem | Esperado | Real | Estado`, con
   estado en `pagado` / `a confirmar` / `pendiente`. Es la sección que justifica el informe.
7. **Mayores gastos** — `d.porDescripcion`, top 10, con posición.
8. **Nota de cierre** — "Generado desde Gastos Familiares. Los montos reflejan los movimientos
   cargados al {fecha}; movimientos cargados después no están incluidos." Sin esa línea, un informe
   guardado de un mes abierto se lee como definitivo.

### Entrega

```ts
const blob: Blob = await new Promise(r => pdfMake.createPdf(docDefinition).getBlob(r));
const nombre = `gastos-${mes}${soloPorcentajes ? '-sin-montos' : ''}.pdf`;
const file = new File([blob], nombre, { type: 'application/pdf' });

// Share sheet nativa donde exista (es una PWA en Android: es el camino natural).
if (navigator.canShare?.({ files: [file] })) {
  try {
    await navigator.share({ files: [file], title: `Gastos ${mes}` });
    return;
  } catch (e) {
    // AbortError = el usuario cerró el share sheet. No es un error: no cae a descarga,
    // porque bajarle un archivo a alguien que acaba de cancelar es peor que no hacer nada.
    if ((e as Error).name === 'AbortError') return;
    console.error('[informeMensual] share falló, cae a descarga:', e);
  }
}
// Fallback: descarga local (mismo patrón que patrimonioInforme.ts).
```
