# F9.115 — Exportar corrida vigente y dossier de análisis

> Estado del repo al auditar: `origin/main` en `c33e9fb` ("F9.114 — Valuacion en USD: TC del dia para lo ya movido, TC de hoy para lo vivo"). Los números F9.114 y anteriores están tomados.

## Problema

La app ingiere corridas pero no las devuelve. Los únicos botones de descarga existentes son el del prompt de chat (`src/vistas/Patrimonio.tsx:3127`, función `descargar()`) y el del informe PDF archivado (`src/vistas/Patrimonio.tsx:883`, vía `downloadURL`). Consecuencia: el `.txt` de una corrida existe únicamente donde el usuario lo guardó al generarlo; si lo perdió, los datos están en Firestore pero son inaccesibles fuera de la UI.

Esto bloquea dos cosas: reconstruir una corrida anterior, y llevar la cartera completa a un análisis externo.

## Alcance

### Sección 1 — `exportarCorridaTxt()`

Nueva función exportada en `src/datos/patrimonio.ts`.

- Firma: `exportarCorridaTxt(fechaCorrida?: string): Promise<{ nombre: string; contenido: string } | null>`
- Sin argumento usa la corrida vigente; con argumento exporta esa corrida (habilita reconstruir históricas).
- Arma un `CorraidaJSON` mapeando cada `Posicion` a `PosicionRaw`: **descartar** `valorUsd`, `tcUsado` y `fechaCorrida`, conservar los 11 campos del schema.
- `meta` se reconstruye desde el snapshot: `fecha_corrida`, `entidad: 'familia'`, `fuentes`, `total_declarado_usd: totalInvertibleUsd`.
- Serializa con `JSON.stringify(obj, null, 2)`.
- `nombre` = `patrimonio_${fechaCorrida}.txt`.
- Devuelve `null` si no hay snapshot. No lanza.

**Criterio de round-trip (innegociable):** el archivo exportado tiene que poder subirse a Patrimonio → ingesta → Paso 1 y pasar la validación de esquema sin un solo error. Si el validador de `PatrimonioIngesta.tsx` rechaza el archivo, la feature no está terminada.

El round-trip es determinístico y no depende de la fecha en que se reimporte: la ingesta resuelve el TC con `tcParaFecha(fecha_corrida)` (`src/vistas/PatrimonioIngesta.tsx:138`) y enriquece con ese valor (`:58-64`), así que reimportar el mismo archivo recalcula exactamente los mismos `valorUsd`. Si el diff **no** da vacío, es un bug real del export, no un efecto del tipo de cambio — no descartarlo por esa vía.

### Sección 2 — `exportarDossierJson()`

Nueva función exportada en `src/datos/patrimonio.ts`. Propósito distinto: análisis externo, **no** re-importable.

```ts
{
  generadoEn: string,            // ISO
  corrida: { meta, posiciones },  // idéntico a la sección 1
  manuales: PosicionManual[],
  flujos: Array<{ fecha: string, tipo, montoUsd, cuenta, nota }>,  // Timestamp → ISO
  historial: SnapshotResumen[],   // hasta 24
  retorno: PeriodoRetorno | null  // calcRetorno(historial, flujos); null si no hay flujos
}
```

Nombre: `dossier_patrimonio_${fechaCorrida}.json`.

**Fail-soft por bloque:** si `cargarFlujos()` falla, `flujos: []` y `retorno: null`, y el resto se exporta igual. Ídem `historial` y `manuales`. Un bloque caído nunca aborta el dossier. Cada fallo se loguea con `console.error` incluyendo el error real, nunca un mensaje hardcodeado.

### Sección 3 — UI

En `ResumenTab` (`src/vistas/Patrimonio.tsx:722`), dentro de la card de informes que ya existe, agregar una fila con dos botones:

- **"Descargar corrida (.txt)"** → sección 1. Subtítulo: "Re-importable en la ingesta".
- **"Descargar dossier (.json)"** → sección 2. Subtítulo: "Corrida + manuales + flujos + historial".

Reusar el patrón de `descargar()` (`:3127`): `new Blob([contenido], { type: 'text/plain' })`, `URL.createObjectURL`, `a.download`, `a.click()`, y `URL.revokeObjectURL` después (el `descargar()` actual no lo hace — **no** tocarlo en esta feature, solo no repetir la omisión en el código nuevo).

Estado `descargando` para deshabilitar el botón mientras corre. Si la función devuelve `null`, toast "No hay corrida cargada" y no descargar nada.

## Fuera de alcance

- Exportar a CSV o XLSX.
- Renombrar el tipo `CorraidaJSON`.
- Exportar activos fijos (no forman parte del schema de ingesta).
- Cualquier cambio en `PatrimonioIngesta.tsx`.

## Criterios de cierre

1. `npx tsc --noEmit` corrido **antes** de empezar y **después**: registrar ambos conteos en el reporte. Cero errores nuevos sobre la línea base.
2. `npm run build` sin errores.
3. Round-trip demostrado: exportar la corrida vigente, subir ese mismo archivo a la ingesta, y que el Paso 3 muestre un diff **vacío** contra la corrida vigente. Pegar captura o el conteo de diferencias.
4. Dossier descargado y abierto: pegar las primeras 20 líneas del JSON generado.
5. Fail-soft verificado: simular fallo de `cargarFlujos()` y confirmar que el dossier igual se genera con `flujos: []`.
6. **Evidencia de push obligatoria.** Pegar la salida literal de:
   ```
   git push origin main
   git log --oneline origin/main -1
   ```
   Sin esa salida la feature no se considera entregada. No alcanza con decir "pusheado".
