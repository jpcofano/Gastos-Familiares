## 1. Causa raíz — medida, no inferida

Dos requests a la misma URL, desde la misma IP residencial argentina, contra el mismo POP de CloudFront (`EZE50-P7`), con 22 segundos de diferencia:

```
curl "https://estadisticas.cafci.org.ar/fondos/216?clase=1634"
     -A "Mozilla/5.0" -H "Accept: text/html,application/xhtml+xml"
→ HTTP/1.1 403 Forbidden · Server: CloudFront · X-Cache: Error from cloudfront

curl (misma URL)
     -H "User-Agent: Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36 (KHTML, like Gecko) Chrome/126.0.0.0 Safari/537.36"
     -H "Accept: text/html,application/xhtml+xml,application/xml;q=0.9,*/*;q=0.8"
     -H "Accept-Language: es-AR,es;q=0.9"
→ HTTP/1.1 200 OK · 23776 bytes · Server: nginx/1.18.0 · X-Cache: Miss from cloudfront
```

Los headers del primer curl son **exactamente** los que manda la función (`index.ts:3501-3506`). Única variable entre 403 y 200: los headers.

**Queda descartado** el origen (IP/ASN de compute): el 403 se reproduce desde una IP residencial. Esa fue la hipótesis que costó tres frentes de investigación en F9.102.x — esta vez se descarta con una medición, no con un razonamiento.

Confirmación del lado servidor (`firebase functions:log`, 2026-07-31T14:39:27, los 13 fondos):

```
HTTP 403 — <TITLE>ERROR: The request could not be satisfied</TITLE> … <H1>403 ERROR</H1>
```

Página de error genérica de CloudFront, consistente con bloqueo en el borde por reglas de bot/WAF.

## 3. Cambios

### Parte 1 — Headers de navegador completos

Constante a nivel de módulo, junto al resto de las constantes CAFCI:

```ts
// F9.112 — CloudFront rechaza con 403 el UA recortado 'Mozilla/5.0'. Medido el 31/07/2026:
// misma IP y mismo POP (EZE50-P7), sólo cambiando headers → 403 vs 200. NO es bloqueo por
// origen/ASN (se reproduce desde IP residencial argentina). Este set es el que devolvió 200.
// NO agregar 'Accept-Encoding': undici lo maneja y lo decodifica solo; forzarlo devuelve
// bytes comprimidos sin decodificar.
const HEADERS_NAVEGADOR = {
  'User-Agent': 'Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36 (KHTML, like Gecko) Chrome/126.0.0.0 Safari/537.36',
  'Accept': 'text/html,application/xhtml+xml,application/xml;q=0.9,*/*;q=0.8',
  'Accept-Language': 'es-AR,es;q=0.9',
} as const;
```

Usarla en el `fetch` de 3501. **No** volver a agregar `Origin`/`Referer`: eran spoofeo de la API vieja, no participaron de la medición y no hay evidencia de que hagan falta.

### Parte 2 — Timeout por fetch y presupuesto de lote (era F9.107)

Con 13 fondos en serie contra `timeoutSeconds: 120`, un solo fetch colgado se come el presupuesto entero y la función muere sin devolver nada — el usuario vuelve a ver `internal` en vez de los errores por fondo.

```ts
const TIMEOUT_FETCH_MS  = 15_000;   // por fondo
const PRESUPUESTO_MS    = 100_000;  // del lote, con margen sobre los 120s de la función

// dentro del loop, antes del fetch:
if (Date.now() - inicioLote > PRESUPUESTO_MS) {
  errores.push({ fondo: fondo.nombre, mensaje: 'Sin tiempo en el lote — reintentá o usá "Pegar JSON".' });
  continue;   // sigue el loop para registrar los que faltan, no corta en seco
}
const res = await fetch(url, { headers: HEADERS_NAVEGADOR, signal: AbortSignal.timeout(TIMEOUT_FETCH_MS) });
```

`inicioLote = Date.now()` se declara junto a `fechaFetch`. El `AbortSignal.timeout` tira `TimeoutError`, que cae en el `catch` por fondo y queda registrado como cualquier otro error — sin cambios en el manejo.

### Parte 3 — Que el error diga qué pasó

El `slice(0, 150)` corta justo antes del `<TITLE>`, que es la única parte informativa de la página de CloudFront. Extraerlo:

```ts
if (!res.ok) {
  const body  = await res.text();
  const title = body.match(/<TITLE>([^<]*)<\/TITLE>/i)?.[1]?.trim() ?? '';
  console.error(`[sincronizarCafci] ${fondo.nombre}: HTTP ${res.status} — ${title || '(sin title)'} — ${body.slice(0, 300)}`);
  throw new Error(`HTTP ${res.status}${title ? ` — ${title}` : ''}: ${body.slice(0, 120)}`);
}
```

Así el toast del cliente muestra `HTTP 403 — ERROR: The request could not be satisfied` en vez de un `<!DOCTYPE HTML PUBLIC …` que no dice nada.

## 5. Riesgo asumido y salida de respaldo

Esto es scraping contra un WAF: la regla puede endurecerse de nuevo y volver a romper la ingesta. Se asume a propósito, con dos mitigaciones ya existentes:

- `importarCafciManual` (el botón *Pegar JSON*) sigue siendo el camino de respaldo y no depende de la red de la función.
- El mensaje de error ahora es diagnóstico por sí solo (Parte 3), así que el próximo bloqueo no arranca de cero.

**Fuera de alcance:** paralelizar los fetches (con timeout y presupuesto ya alcanza), reintentos con backoff, y cachear el HTML entre corridas.
