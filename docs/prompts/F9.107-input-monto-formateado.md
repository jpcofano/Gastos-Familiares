# F9.107 — Input de monto formateado (es-AR) y parser robusto

**Estado:** pendiente de implementación
**Ruta destino en repo:** `docs/F9.107_input_monto_formateado.md`
**Auditado sobre:** `origin/main`, clone limpio

## 1. Síntoma reportado

El campo `Monto` del form de alta/edición muestra el valor crudo (`184245.43`) en vez del formato es-AR (`184.245,43`).

## 2. Hallazgo mayor (auditoría)

El síntoma cosmético convive con un bug de **corrupción silenciosa de datos**.

### 2.1 Inputs crudos (evidencia)

`src/vistas/AltaMovimiento.tsx:340-351`

El design system **ya tiene** el formateador canónico en `src/design-system/components/core/Money.tsx:16`

No existe contraparte de input: `src/design-system/components/core/` contiene

## 3. Decisiones de diseño

| # | Decisión | Alternativa descartada | Razón |
|---|---|---|---|
| D1 | Formateo **on-blur**, no live mask | máscara mientras se tipea | la máscara viva reposiciona el caret en cada tecla; roto en Android/PWA |
| D2 | Input **sin símbolo de moneda** | `$ 184.245,43` dentro del input | el `FieldRow label="Moneda"` inmediatamente debajo ya lo indica; evita doble fuente de verdad ARS/USD |
| D3 | Contrato **numérico**: `value: number \| null` | seguir pasando string | elimina la ambigüedad de raíz — el parser solo ve tecleo humano, nunca `String(m.monto)` |
| D4 | `1.234` (un separador, 3 dígitos después) → **1234** | → `1.234` | convención es-AR; los 6 call sites son montos y TC (~1450), nunca fracciones de 3 decimales |
| D5 | Parse fallido → **no guarda**, error visible | fallback a 0 | fail-soft ≠ fail-silent: nunca persistir un número que el usuario no tipeó |

## 4. Implementación

### 4.1 Util nuevo — `src/design-system/utils/monto.ts`

```ts
/**
 * Parsea un monto tipeado por un humano. Tolera es-AR (1.234,56),
 * en-US (1,234.56), símbolos de moneda y espacios (incl. NBSP).
 * Devuelve null si no se puede interpretar de forma inequívoca.
 */
export function parseMonto(raw: string): number | null;

/** Formatea a es-AR sin símbolo: 184245.43 → "184.245,43" */
export function formatMonto(n: number, decimals?: number): string;
```

Algoritmo de `parseMonto`:

1. Normalizar: `trim()`, quitar `\s` y `\u00A0`, quitar prefijo `U$S | US$ | $` (case-insensitive).
2. Si no matchea `/^-?[\d.,]*$/` o no tiene dígitos → `null`.
3. Ubicar `lastIndexOf(',')` y `lastIndexOf('.')`.
4. **Ambos presentes** → el *posterior* es decimal; el otro es de miles: se elimina.
5. **Uno solo, repetido** → todos de miles: se eliminan.
6. **Uno solo, único** → si tiene exactamente 3 dígitos a la derecha **y** al menos 1 a la izquierda → miles (D4); si no → decimal.
7. `Number(normalizado)`; devolver `null` si `!Number.isFinite`.

Tests obligatorios (`monto.test.ts`) — la tabla de §2.3 completa, más:
`''` → null, `'abc'` → null, `','` → null, `'0'` → 0, `'-5,50'` → -5.5, `'1.234.567,89'` → 1234567.89.

### 4.2 Componente nuevo — `src/design-system/components/core/MoneyInput.tsx`

```tsx
interface MoneyInputProps {
  value: number | null;
  onChange: (n: number | null) => void;
  moneda?: 'ARS' | 'USD';
  decimals?: number;      // default 2
  placeholder?: string;   // default '0,00'
  id?: string;
  required?: boolean;
  autoFocus?: boolean;
}
```

Comportamiento:

- Buffer string interno (`useState`). Mientras hay foco, **se respeta exactamente lo tecleado** — sin reformatear.
- En cada `onChange`: `parseMonto(buffer)` → notifica al padre (`number | null`). El padre nunca ve strings.
- En `onBlur`: si parseó OK → reescribe el buffer con `formatMonto(n)`. Si no → deja el texto crudo (el usuario ve lo que escribió y lo puede corregir).
- En `onFocus`: `select()` — permite pisar el valor de un tirón, importante en el flujo de comprobante precargado.
- Si `value` cambia desde afuera **y el input no tiene foco** → resincroniza el buffer con `formatMonto(value)`. Con foco, no se toca (evita pisar el tecleo).
- Estilo: `fontFamily: 'var(--font-num)'`, `fontVariantNumeric: 'tabular-nums'`, alineado a la derecha — consistente con `Money.tsx:39-41`.

Notas por sitio:

- **`AltaMovimiento.tsx:96`** — `useState(preload?.monto ?? '')`. El preload viene de OCR de comprobante como string. Convertir en el borde: `parseMonto(preload?.monto ?? '') `. Si el OCR devuelve algo no parseable, `null` → el form queda vacío y pide el monto, en vez de guardar basura.
- **`AltaMovimiento.tsx:208-210`** — la guarda `isNaN(montoNum) || montoNum <= 0` pasa a ser `montoNum === null || montoNum <= 0`. Mantener el mismo mensaje de error.
- **`AltaMovimiento.tsx:282`** — `autoConfirmar` dispara guardado sin UI. Verificar que con `monto === null` **aborte** y llame `onErrorAuto`, nunca que persista 0.
- **`EditarMovimiento.tsx:111`** — `if (montoNum !== m.monto) cambios.monto = montoNum`. Con `null` no debe entrar en `cambios` (el early-return de validación ya lo cubre; confirmar).

## 5. Fail-soft

- `parseMonto` nunca tira: devuelve `null`.
- `MoneyInput` con `value` no finito (`NaN`, `Infinity`) → renderiza vacío, no `"NaN"`.
- Un sitio migrado que falle no bloquea a los otros: la migración es archivo por archivo, cada uno commiteable de forma independiente.
- **Prohibido** el fallback `|| 0` en cualquier ruta que persista (D5).

## 6. Criterios de cierre

1. `src/design-system/utils/monto.ts` existe y exporta `parseMonto` y `formatMonto`.
2. `src/design-system/components/core/MoneyInput.tsx` existe.
3. Tests de `parseMonto` pasan, incluyendo la tabla completa de §2.3 y los casos borde de §4.1.
4. `grep -rn --include=*.ts --include=*.tsx "replace(',', '.')" src functions` → **0 resultados**. Este grep vacío es la evidencia positiva de que las 9 ocurrencias se eliminaron.
5. `grep -rn --include=*.tsx 'inputMode="decimal"' src` → solo dentro de `MoneyInput.tsx`.
6. `tsc --noEmit` en baseline: registrar el conteo de errores al inicio de sesión y demostrar **0 errores nuevos**. Recordar que `tsconfig.json` debe incluir `src/**/*.tsx` (Vite/esbuild no typechequea).
7. Verificación manual en el caso del reporte: alta con descripción `Cons.Prop.Pje del Signo 4032/42`, monto `184245.43` → al salir del campo muestra **`184.245,43`**; el preview y lo persistido en Firestore coinciden en `184245.43`.
8. Verificación de regresión: tipear `184.245,43` a mano → persiste `184245.43` (hoy persiste `184.245`).
9. **Evidencia de push obligatoria:** salida real de `git push` + `git log --oneline origin/main -1`. Sin eso el spec no se considera cerrado. No se acepta auto-reporte de completitud.
10. Deploy: `npm run build` manual y luego `firebase deploy --only hosting` (no hay Cloud Functions tocadas en este spec). Verificar en incógnito sobre la URL de Hosting; si el service worker sirve caché viejo, "borrar datos del sitio".
