## 1. Objetivo

### 1.1 Arbitraje (hueco que dejó F9.110)

F9.110 resuelve "dueño explícito vs heurística". **No resuelve "heurística vs heurística".** Si un movimiento no tiene `itemEsperadoId`, el filtro de F9.110 lo deja disponible para *todos* los ítems y dos ítems con `matchTexto` solapado lo siguen contando dos veces.

Regla nueva: **un movimiento lo reclama un solo ítem.** Gana el más específico — coincidencia exacta de categoría+subcategoría por encima de `matchTexto`. Empate ⇒ desempate determinístico **y la ambigüedad se muestra**, no se duplica en silencio.

### 1.2 Tokens de `matchTexto` (causa raíz compartida)

`incluye`/`excluye` se evalúan con `includes()` crudo: sin límite de palabra y sin largo mínimo. `'glob'` matchea `"BODEGON EL GLOBITO SRL"`; `'sa'` matchea medio mundo. Es el mismo defecto detrás del falso positivo del Bodegón (F9.109) y de los ítems que se llevan movimientos ajenos.

## 3. Parte 1 — Resolvedor con arbitraje (`src/datos/checklist.ts`)

### 3.1 Puntaje de reclamo

**El predicado de "quién puede reclamar" no cambia** respecto de hoy (salvo el `coincideToken` de la Parte 2). Lo nuevo es el puntaje de especificidad:

```ts
// F9.111 — puntaje de especificidad de un reclamo. null = el ítem no reclama el movimiento.
// El predicado es idéntico al de movimientosDelItem (checklist.ts:14-32); lo único nuevo es
// el score, que decide quién gana cuando más de un ítem reclama el mismo movimiento.
function puntajeReclamo(item: ExpectedItem, m: Movement): number | null {
  if (item.tarjetaCodigo) {
    return (m.subtipo === 'TarjetaPago' && m.tarjetaCodigo === item.tarjetaCodigo && m.moneda === item.moneda) ? 8 : null;
  }
  if (m.tipo !== item.tipo)   return null;
  if (m.moneda !== item.moneda) return null;

  const cat    = item.categoria    !== null && m.categoria    === item.categoria;
  const subcat = item.subcategoria !== null && m.subcategoria === item.subcategoria;

  if (item.matchTexto) {
    const desc = (m.descripcion ?? '').toLowerCase();
    if (!item.matchTexto.incluye.some(t => coincideToken(desc, t))) return null;
    if ( item.matchTexto.excluye.some(t => coincideToken(desc, t))) return null;
    return 1 + (cat ? 2 : 0) + (subcat ? 2 : 0);   // el texto solo es lo MENOS específico
  }

  if (item.categoria    !== null && m.categoria    !== item.categoria)    return null;
  if (item.subcategoria !== null && m.subcategoria !== item.subcategoria) return null;
  if (item.tipo === 'Ingreso' && item.persona !== null && m.persona !== item.persona) return null;
  return (cat ? 2 : 0) + (subcat ? 2 : 0) + (item.tipo === 'Ingreso' && item.persona !== null ? 1 : 0);
}
```

Escala: `tarjetaCodigo` 8 · cat exacta +2 · subcat exacta +2 · `matchTexto` +1 · persona (Ingreso) +1. Un `null` en el ítem es comodín y **no suma** — comodín es menos específico que coincidencia.

Control con el caso real (movimiento AySA `Casa/Agua`):

| Ítem | cat | subcat | texto | score |
|---|---|---|---|---|
| `Casa › Agua` (`incluye:['aysa']`) | ✓ +2 | ✓ +2 | ✓ +1 | **5 — gana** |
| `Auto › Agua` (`incluye:['aysa']`) | ✗ 0 | ✓ +2 | ✓ +1 | 3 |

### 3.2 Dos pases

```ts
export interface CheckItem {
  item: ExpectedItem;
  matches: Movement[];
  estado: EstadoChecklist;
  disputas?: { movId: string; otros: string[] }[];   // F9.111 — empates arbitrados
}

export function calcularChecklist(items: ExpectedItem[], movs: Movement[], mes: string): CheckItem[] {
  const mesHoy       = mesActualStr();
  const idsConocidos = new Set(items.map(i => i.id));      // activos + inactivos: un ítem
  const activos      = items.filter(i => i.activo);        // desactivado sigue siendo dueño
  const porItem   = new Map<string, Movement[]>();
  const disputas  = new Map<string, { movId: string; otros: string[] }[]>();
  const asignados = new Set<string>();

  // Pase 1 — vínculo directo (manda sobre todo). Un itemEsperadoId colgado (ítem borrado)
  // NO se asigna acá: queda disponible para el pase 2 y no se pierde del checklist.
  for (const m of movs) {
    if (m.itemEsperadoId && idsConocidos.has(m.itemEsperadoId)) {
      push(porItem, m.itemEsperadoId, m);
      asignados.add(m.id);
    }
  }

  // Preserva checklist.ts:10-11 — el ítem con vínculo directo NO participa de la heurística.
  const candidatos = activos.filter(i => (porItem.get(i.id)?.length ?? 0) === 0);

  // Pase 2 — arbitraje: cada movimiento libre va a UN solo ítem.
  for (const m of movs) {
    if (asignados.has(m.id)) continue;
    const reclamos = candidatos
      .map(i => ({ id: i.id, score: puntajeReclamo(i, m) }))
      .filter((r): r is { id: string; score: number } => r.score !== null);
    if (reclamos.length === 0) continue;

    // Mayor score gana; empate ⇒ menor id lexicográfico (determinístico e independiente
    // del orden en que Firestore devuelva los ítems).
    reclamos.sort((a, b) => b.score - a.score || (a.id < b.id ? -1 : 1));
    const ganador = reclamos[0];
    push(porItem, ganador.id, m);
    asignados.add(m.id);

    // Sólo es ambigüedad cuando EMPATAN en el máximo: ahí el desempate es arbitrario y hay
    // que mostrarlo. Si el ganador gana por score, el arbitraje es correcto y no molesta.
    const empatados = reclamos.filter(r => r.score === ganador.score);
    if (empatados.length > 1) {
      push(disputas, ganador.id, { movId: m.id, otros: empatados.slice(1).map(r => r.id) });
    }
  }

  return activos
    .map(item => {
      const matches = porItem.get(item.id) ?? [];
      return { item, matches, estado: estadoItem(item, matches, mesHoy, mes), disputas: disputas.get(item.id) };
    })
    .sort((a, b) => ORDEN_ESTADO[a.estado] - ORDEN_ESTADO[b.estado]);
}
```

## 4. Parte 2 — `coincideToken` con límite de palabra y largo mínimo

### 4.1 La función

```ts
// F9.111 — matcheo de tokens con límite de palabra. Antes era includes() crudo, así que
// 'glob' matcheaba "BODEGON EL GLOBITO SRL" y 'sa' matcheaba cualquier razón social.
// Sin lookbehind a propósito: no está disponible en todos los WebView de Android/iOS viejos.
export const LARGO_MINIMO_TOKEN = 3;

const esAlfanum = (c: string) => /[\p{L}\p{N}]/u.test(c);

export function coincideToken(texto: string, patron: string): boolean {
  const p = patron.trim().toLowerCase();
  if (p.length < LARGO_MINIMO_TOKEN) return false;   // token demasiado corto: se ignora
  const t = texto.toLowerCase();
  for (let i = t.indexOf(p); i !== -1; i = t.indexOf(p, i + 1)) {
    const antes = i === 0 ? '' : t[i - 1];
    const desp  = t[i + p.length] ?? '';
    if ((!antes || !esAlfanum(antes)) && (!desp || !esAlfanum(desp))) return true;
  }
  return false;
}
```

Comportamiento esperado: `'glob'` ✗ `"bodegon el globito srl"` · `'aysa'` ✓ `"aysa s.a."` · `'edesur'` ✓ `"pago edesur 07/26"` · `'sa'` ✗ siempre (menos de 3).

### 4.2 Dónde se usa y el fallback

- `checklist.ts` — dentro de `puntajeReclamo` (§3.1).
- `functions/src/matchLogica.ts:119-125` — `evaluarMatchTexto` pasa a usar la **misma** implementación, copiada con el comentario de gemelo que ya existe en la línea 119 (los dos paquetes no comparten código). Si se toca una, se tocan las dos: dejarlo escrito ahí.
- **Fallback obligatorio**: si **ningún** token de `incluye` llega al largo mínimo, el ítem se trata como si **no tuviera** `matchTexto` (cae a categoría+subcategoría) en vez de dejar de matchear todo. Sin esto, un ítem con `incluye:['sa']` deja de capturar en silencio.
