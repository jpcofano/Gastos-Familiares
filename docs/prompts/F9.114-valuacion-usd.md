## 1. Regla de negocio (definida por el dueño)

El criterio no es "mes actual vs mes viejo": es **plata que ya se movió vs plata que todavía está**.

| Qué | TC de valuación | Por qué |
|---|---|---|
| Gasto ya pagado (movimiento) | El del **día del movimiento** | Ya saliste de esos pesos a ese dólar. Congelado. |
| Ingreso ya recibido, en meses cerrados | El del **día del movimiento** | Entró a ese dólar. Congelado. |
| Gasto esperado **no pagado** | **TC de hoy** | Lo vas a pagar con pesos de hoy. |
| Ingreso del **mes en curso** | **TC de hoy** | Está en el banco desvalorizándose. |

**Cierre de mes (decisión explícita, opción A):** al pasar de mes, los ingresos dejan de valuarse al TC de hoy y quedan congelados al TC de su día. Se asume que esa plata ya se gastó, porque la app no trackea saldos de cuentas. Consecuencia aceptada: el valor en USD de un ingreso **salta** el día 1 del mes siguiente. Es deliberado, no un bug — documentarlo en `CLAUDE.md`.

**Dirección USD → ARS**: sin cambios. Manda `movimiento.tcUsdArs`, el snapshot del día. Un gasto en USD de marzo se muestra en pesos al TC de marzo.

## 2. Auditoría — por qué hoy no convierte

### 2.1 `TC_DEFAULT` hardcodeado (`money.ts:13, 19`)

`Resumen.tsx:249-250` (`fmtBig`/`fmtSmall`) llaman a `fmtMoney` **sin `tc`** → `const tc = opts.tc ?? TC_DEFAULT` → toda conversión visible de Resumen usa el literal `1454`. El comentario de `money.ts:10-12` ya lo declara transitorio.

### 2.2 El TC de los KPIs cae a `1` (`Resumen.tsx:91-93`)

```ts
const conTc = movs.filter(m => m.moneda === 'USD' && m.tcUsdArs).sort(…);
const tc = conTc[0]?.tcUsdArs ?? 1;
```

Si el mes no tiene ningún movimiento en USD —agosto 2026: AySA, Telecom, Edesur, todos ARS— `tc = 1` y el "equivalente USD" queda igual al monto en pesos. Ese es el síntoma reportado.

### 2.3 No existe TC para un movimiento en ARS

`AltaMovimiento.tsx:158` pone `tcUsdArs = null` cuando la moneda es ARS (`if (moneda === 'ARS') { setTcUsdArs(null); return; }`). O sea: **el snapshot sólo existe para movimientos en USD**. Para valuar un gasto en pesos al TC de su día hay que resolverlo por fecha contra `/tcDiario`.

→ No alcanza un TC por pantalla: hace falta un **mapa `fecha → tc`** del mes. Ya existe el loader: `cargarTCRango(desde, hasta)` en `patrimonioOptimizacion.ts:117-135`, que devuelve exactamente eso. **Reusarlo, no escribir otro.**

### 2.4 Movimiento en USD sin TC vale 0 (`Resumen.tsx:70`)

```ts
function arsEq(m) { return m.moneda === 'ARS' ? m.monto : (m.tcUsdArs ? m.monto * m.tcUsdArs : 0); }
```

Un movimiento en USD con `tcUsdArs` nulo suma **0**: desaparece de los totales sin aviso. `AltaMovimiento.tsx:163` ya loguea un warning cuando el lookup falla, así que el caso ocurre.

## 3. Cambios

### Parte 1 — Resolver TC por fecha (`src/datos/tcDiario.ts`)

```ts
// F9.114 — TC de una fecha contra un mapa ya cargado: exacto, o el más reciente anterior
// (fines de semana y feriados no tienen doc). Devuelve null si no hay ninguno anterior.
// NOTA: se respeta la convención existente del cron (la key D guarda el cierre de D−1);
// acá NO se corrige ni se desplaza — sólo se lee como está.
export function tcDeFecha(mapa: Record<string, number>, fecha: string): number | null {
  if (mapa[fecha]) return mapa[fecha];
  const anteriores = Object.keys(mapa).filter(k => k < fecha).sort();
  const ultima = anteriores[anteriores.length - 1];
  return ultima ? mapa[ultima] : null;
}
```

El mapa se carga con margen hacia atrás (§3.2) para que el primer día del mes tenga un anterior disponible.

### Parte 2 — Cargar mapa del mes + TC de hoy (`Resumen.tsx`)

### Parte 3 — Aplicar la regla

**Helper único** — todo pasa por acá, no se convierte a mano en ningún lado:

```ts
// F9.114 — TC con el que se valúa un movimiento en USD. Ver la tabla de la regla en el spec.
// `esVivo` = ingreso del mes en curso (sigue en el banco). Los gastos pagados NUNCA son vivos,
// ni siquiera en el mes en curso: ya se pagaron al dólar de ese día.
function tcDeMovimiento(m: Movement, esMesActual: boolean, mapaTc, tcEfectivo: number): number {
  const esVivo = esMesActual && m.tipo === 'Ingreso';
  if (esVivo) return tcEfectivo;
  return tcDeFecha(mapaTc, isoDe(m.fecha)) ?? tcEfectivo;
}
```

- **`arsEq` (línea 70)**: se mantiene la dirección USD→ARS con el snapshot; sólo cambia el caso sin snapshot (Parte 5).
- **`calcularKpis` (84-100)**: borrar el bloque `conTc` y el `?? 1`. Acumular por movimiento usando `tcDeMovimiento`, en vez de aplicar un TC único a los agregados. El campo `tc` de `Kpis` pasa a ser `tcEfectivo` (lo consumen las líneas 175 y 304, que son cifras **vivas** y por lo tanto van al TC de hoy → correcto).
- **`fmtBig`/`fmtSmall` (249-250)**: reciben el TC que corresponde por fila. En el total del día (`d.eqArs`, líneas 515-516) el equivalente en USD se acumula **por movimiento**, no dividiendo el total del día por un TC único — si no, un día con ingreso y gasto mezcla criterios.
- **`pendienteAgenda` y los esperados no pagados (línea 304)**: `tcEfectivo`, siempre. Son plata que todavía no salió.

### Parte 4 — Fallback en cascada, que se actualiza solo

`TC_DEFAULT` → **`TC_FALLBACK`** (renombrar; el renombre obliga a que `tsc` marque cada call site y que cada uso sea deliberado).

Cascada de tres niveles, y la pantalla **siempre dice cuál está usando**:

1. `/tcDiario` → sin aviso.
2. **Último TC leído con éxito, cacheado en `localStorage`** con su fecha. Se reescribe en cada lectura exitosa, así el fallback se actualiza solo todos los días. Aviso: `TC del {fecha} — no se pudo leer el de hoy.`
3. `TC_FALLBACK = 1454` → sólo si nunca se leyó nada (instalación nueva, primera carga offline). Aviso: `Sin TC — valor de referencia.`

En `tcDiario.ts`, con el patrón `try/catch` que ya usa `comerciosLogos.ts:15-16` (el storage puede estar bloqueado):

```ts
const KEY_TC_CACHE = 'gf-tc-ultimo';
export function guardarTcCache(fecha: string, tc: number) { try { localStorage.setItem(KEY_TC_CACHE, JSON.stringify({ fecha, tc })); } catch {} }
export function leerTcCache(): { fecha: string; tc: number } | null { try { return JSON.parse(localStorage.getItem(KEY_TC_CACHE) ?? 'null'); } catch { return null; } }
```

`cargarTCReciente` llama a `guardarTcCache` en cada éxito. `tcEfectivo = tcHoy ?? leerTcCache()?.tc ?? TC_FALLBACK`.

## 4. Criterios de cierre

1. `npx tsc --noEmit` sin errores nuevos. `npm run build` OK.
2. **Agosto 2026** (sin movimientos en USD): el equivalente en USD deja de ser igual al monto en pesos. Con $316.492 y MEP ~1.454 → ~U$S 218, no U$S 316.492.
3. **Congelado**: un gasto pagado en un mes cerrado muestra el mismo equivalente en USD hoy y mañana, aunque el MEP cambie. Verificable comparando dos días, o pisando `tcHoy` a mano.
4. **Vivo**: un esperado no pagado y un ingreso del mes en curso **sí** cambian su equivalente en USD cuando cambia el TC de hoy.
5. **Histórico USD→ARS intacto**: un gasto en USD sigue mostrándose en pesos al TC de su propio día.
6. Día sin doc en `/tcDiario` (sábado): se usa el TC anterior más cercano, no `TC_FALLBACK`.
7. Cascada: con `/tcDiario` caído, se usa el cache de `localStorage` y se ve `TC del {fecha}…`. Con `localStorage` vacío, `TC_FALLBACK` y el aviso correspondiente.
8. `grep -n "TC_DEFAULT" src` no devuelve nada.
9. Deploy `--only hosting`, verificación en incógnito o *borrar datos del sitio*.
10. **Evidencia pegada**: `git push` + `git log --oneline origin/main -1`.
11. Spec commiteado en `docs/prompts/F9.114-valuacion-usd.md` y la regla (tabla de §1 + salto de cierre de mes) documentada en `docs/CLAUDE.md`.
