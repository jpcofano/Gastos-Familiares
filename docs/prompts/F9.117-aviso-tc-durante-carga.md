# F9.117 — El aviso de TC no debe aparecer mientras carga

> Auditado sobre `origin/main` en `82e2233`. Línea base de `npx tsc --noEmit`: **41 errores**.

## Problema

Al entrar a Resumen o Inicio aparece "TC del YYYY-MM-DD — no se pudo leer el de hoy", aunque el TC de hoy exista y aparezca un segundo después. El mensaje es falso: no es que no se pudo leer, es que todavía no terminó de leer.

## Causa raíz (auditada)

`tcEfectivoDe(tcHoy: number | null)` en `src/datos/tcDiario.ts:106` tiene **dos** estados donde hacen falta **tres**:

```ts
if (tcHoy) return { tc: tcHoy, aviso: null };
const cache = leerTcCache();
if (cache) return { tc: cache.tc, aviso: `TC del ${cache.fecha} — no se pudo leer el de hoy.` };
return { tc: TC_FALLBACK, aviso: 'Sin TC — valor de referencia.' };
```

`null` significa a la vez "todavía no cargó", "resolvió vacío" y "falló la consulta". Los consumidores llaman a la función en cada render (`Resumen.tsx:1004`, `Dashboard.tsx:741`) mientras el fetch está en vuelo, así que durante esa ventana el banner afirma algo que no pasó.

Segundo problema, más chico: `Resumen.tsx:1001` y `Dashboard.tsx:739` setean `null` tanto en el `.catch` como cuando la consulta resuelve sin datos (`h[0]?.tcUsdArs ?? null`). Los dos casos son distintos y hoy dan el mismo mensaje.

## Alcance

### Sección 1 — Tercer estado en `tcEfectivoDe`

Nuevo tipo exportado en `src/datos/tcDiario.ts`:

```ts
export type EstadoTcHoy =
  | { estado: 'cargando' }
  | { estado: 'ok'; tc: number }
  | { estado: 'vacio' }      // la consulta resolvió sin registros
  | { estado: 'error'; err: unknown };
```

`tcEfectivoDe(estado: EstadoTcHoy)` devuelve:

| Estado entrante | `tc` | `aviso` |
|---|---|---|
| `cargando` | cache → `TC_FALLBACK` | **`null`** |
| `ok` | el valor | `null` |
| `vacio` | cache → `TC_FALLBACK` | cache: `TC del {fecha} — todavía no hay TC de hoy.` / sin cache: `Sin TC — valor de referencia.` |
| `error` | cache → `TC_FALLBACK` | cache: `TC del {fecha} — falló la lectura del TC de hoy.` / sin cache: `Sin TC — falló la lectura.` |

Mientras carga se usa el mismo valor de siempre para no hacer saltar los números; lo único que cambia es que **no se afirma nada falso**.

**Compatibilidad:** mantener el overload `tcEfectivoDe(tcHoy: number | null)` con el comportamiento actual, o migrar los 3 call sites en el mismo commit. No dejar llamadas mixtas.

### Sección 2 — Call sites

`Resumen.tsx:997-1004` y `Dashboard.tsx:735-741`: estado inicial `{ estado: 'cargando' }`; en el `.then`, `ok` si vino número y `vacio` si no; en el `.catch`, `error` con el error real. **El `console.warn` debe seguir logueando el error completo**, nunca un texto hardcodeado.

`Patrimonio.tsx:3416` usa `tcEfectivoDe(null).tc` solo para el valor inicial y no muestra aviso: adaptarlo a `{ estado: 'cargando' }` sin cambiar comportamiento.

**Fail-soft:** si `leerTcCache()` tira (localStorage bloqueado), cae a `TC_FALLBACK` sin romper la pantalla. Ya está contemplado en `tcDiario.ts:96-101`; no regresionarlo.

## Fuera de alcance

- Cambiar `TC_FALLBACK` o la cascada.
- Tocar el cartel de "TC estimado" por movimiento (`Resumen.tsx:635`), que es otra cosa.
- El cron de `tcDiario`.

**El tripwire dispara: `tcEfectivoDe` ya recibía un estado de carga** antes de recibir esta spec.
La spec está auditada sobre `82e2233`, pero el backlog `docs/prompts/backlog-post-F9.116.md`
—que describe este mismo bug con la misma causa raíz— se ejecutó en `9d6b6d9`, donde ya se
introdujo `EstadoTcHoy` con los cuatro estados y se migraron los tres call sites.

Lo que faltaba respecto de **esta** spec, y se completó ahora:

- `error` pasa a llevar el error real (`{ estado: 'error'; err: unknown }`), que antes se
  descartaba después de loguearlo. Ahora también viaja al módulo puro.
- Los cuatro textos de aviso se alinean palabra por palabra con la tabla de la Sección 1. En
  particular, `error` con cache dice "falló la lectura del TC de hoy" (antes decía "no se pudo
  leer el de hoy", que era el texto viejo de F9.114 y no distinguía de `vacio`).
- Se agrega `<1%`… no aplica acá; ver F9.119.

**Compatibilidad:** se migraron los 3 call sites en el mismo commit, no se dejó overload — la
spec permite cualquiera de las dos y no quedan llamadas mixtas (`grep tcEfectivoDe` da 3 usos,
todos con `EstadoTcHoy`).

`tsc`: 41 → 41. Criterios 3, 4 y 5 requieren la app corriendo.
